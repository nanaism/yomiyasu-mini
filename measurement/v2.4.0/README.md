# 本体 v2.4.0 と mini 1.1.0 の測定の記録

この記録は本体 v2.4.0 から作った mini 1.1.0 の測定です。いまの mini は本体 v2.5.0 から作り直し、[../README.md](../README.md) で測りました。

本体 yomiyasu v2.4.0 と yomiyasu-mini 1.1.0 に同じ原稿を推敲させ、書き直した文を本体 v2.4.0 の検査で数えました。1本ごとの数は [results.json](./results.json) にあります。本体 v2.2.2 から作った mini 1.0.0 の測定は [v2.2.2/README.md](../v2.2.2/README.md) にあります。

## 測り方

- 原稿: 本体 v2.4.0 の `tests/corpus/` から、`raw_ai/` の26本、`blacklist_ai/` の24本、`edge_cases/` の1本（`edge_kiku_45`）。mini 1.0.0 の測定と同じ51本で、どれも3回ずつ推敲させました。
- 推敲させたもの: Claude Code 2.1.296 の claude-opus-5-5 で、effort は high です（`claude --print --model claude-opus-5-5 --effort high`）。本体と mini で同じモデルと設定を使いました。`--setting-sources project` を付けて利用者の設定を読ませず、CLAUDE.md と AGENTS.md を `claudeMdExcludes` で外し、MCP のサーバーも外しました。使える道具は Bash、Read、Write、Edit、Skill です（Agent、WebFetch、WebSearch は外しています）。
- 頼み方: 推敲の1回ごとに空の作業フォルダを作り、原稿を `draft.md` として置き、スキルを `.claude/skills/` の下に写しました。そのうえで「draft.md を yomiyasu で読みやすくして、結果を out.md に書いてください。」と頼みました（mini は「yomiyasu-mini で」）。使われたスキルが測るスキルだけであることを、1回ごとに Claude Code の記録で確かめています。
- 数え方: 原文と最終稿を本体 v2.4.0 の `yomiyasu_diff.py 原文 最終稿 --fail-on meaning-risk --json` に渡しました（`--doc-type` と `--stance` は渡していません）。「数える恐れ」は、`--fail-on meaning-risk` が数える意味が変わる恐れです。残った候補は `yomiyasu_lint.py 最終稿 --json` の warn 以上で数えました。書き換えた量は、`difflib.SequenceMatcher(autojunk=False)` で一致しない区間ごとに原文と最終稿の長いほうの字数を足し、原文の空白を除いた字数1,000字あたりにした値です。入力トークンは Claude Code の記録の usage にある input_tokens、cache_creation_input_tokens、cache_read_input_tokens の合計です。
- 測っている途中で、測定に使ったアカウントの利用上限に達し、本体の3回分と mini の60回分の推敲が止まりました。上限が解けてから、止まった分だけをもう一度流しています。

## 恐れを1件ずつ読んだ結果

本体の1件と mini の3件はどれも `blacklist_ai/07_code_review_sonnet_casual` の同じ文で、diff は文の種類が変わった恐れとして数えています。原稿では「提案は三つです。」のあとに、「まずDBアクセスは…切り出してください。」「次に決済APIの呼び出しは…インターフェースの裏に隠し、サービスからはHTTPの詳細が見えないようにします。」が続きます。

- mini は3回とも、2つ目の提案の文末「…見えないようにします。」を「…見えないようにしてください。」にしました。1つ目の提案と同じ依頼の形にそろえたものです。説明の形の提案を依頼に上げたので、言い切りの強さが1段上がっています。
- mini は3回とも、返事の「変えたところ」にこの変更と理由（「〜します」のままでは、レビューする側が自分でする作業にも読める。1つ目の提案と同じ依頼にそろえた）を書きました。
- 1回目と3回目は、この変更を「書き手に確かめたい点」にも出しています。1回目は、強く頼みすぎだと感じるなら元の「〜ようにします」に戻せると書き、3回目は、状態の説明として書いた文なら元の「〜します」に戻すように書いています。
- mini の1回目は同じ文の「インターフェースの裏に隠し」も「インターフェースを通して呼び出す形にし」にしていて、返事には英語の直訳調をやめたと書いています。diff はこの言い換えを数えていません。
- 本体は1回目に、同じ文の文末を mini と同じ「…見えないようにしてください。」にしました。2回目と3回目は「…見えないようにします。」のまま残しています。
- mini 1.0.0 の測定（Codex CLI、本体 v2.2.2）でも、mini はこの文の文末を同じように依頼にしていました。

ほかに数える恐れはありませんでした。

## 入れた決まりと外したもの

意味を守る決まりは SKILL.md の本文に置き、測定で外さない部品にしています。

意味の保持（最優先ルール）、情報が足りないときの暫定文、専門用語と名称の扱い、言い直しテストは、本体の文をそのまま写しました。置き換えたのは、mini にない道具やファイルを指す句だけです。情報を足さないことは、本体の節の最初の2段落をそのまま写し、AIへの指示が本文に残った文の段落を短く書き直しました（全文は `references/rules.md`）。言い切りの強さを上げないことは本体の「文書の立場と文末」から、条件・否定・因果・時系列を保つことは「段落と文の論理構造（つながり）」から、短く書き直して入れました。細部は参照ファイルに写しています。

本体の SKILL.md のほかの節は、短く書き直して SKILL.md に置き、SKILL.md に入らなかった文と事例を `references/rules.md` と `references/doc-types.md` に写しました。本体 v2.3.0 と v2.4.0 で足された決まりのうち、次のものを入れています。

- 英語の短い術語に当てた漢字1字の名詞（版、頭、印）を、直訳語の4つ目の型として SKILL.md に入れ、細部と事例を `references/rules.md` に写しました。
- 他動詞を1語だけ名詞にして「の」で受ける形（「結果の確かめ」）の段落は、`references/rules.md` に写し、SKILL.md には直し方を述べる1文と、rules.md の節への案内だけを置きました。SKILL.md の字数の上限に収めるためです。
- スライドの見出しと1行の箇条で間を作るだけの読点を外す決まりと、スライドの前後に付いた依頼者あての前置きや注記を残す決まりは、`references/doc-types.md` のスライドの節に写しました。

外したのは、おもに mini にない道具に関わる手順と出力の欄です。lint の規則の名前、diff の文体の硬化と勢いの検査、check の実行の記録（run と verify）、資料から事実を補う手順と「事実の確かめ」の欄、lint が読む語のファイル（`references/lists/`）、Step 5「提出の前の照合」がこれに当たります。Step 5 のうち、残った直訳語と flag.txt の語を見直す確かめだけは、Step 4 の目で見る点検に書き直して入れました。本体 v2.4.0 の diff の「原文にない人や担当を足した文」の候補も入れていません。入れなかったのは、本体のこの部分のコードが約24.5KBあり、入れると検査のスクリプトがもう1本要って、配るファイルが8つを超えるためです。ほかに、本体の「情報の不増補」の、相対の日付に日付を添える段落を入れていません。参照ファイルのうち、slop-catalog.md の3章（lint の語彙と同じ一覧）、gemini-syntax.md の調査の節と原則2〜14（SKILL.md や写した節と重なる）、persona.md と audience.md の一部の章（読む場面と決め方、読者像、例など）も写していません。部品ごとの扱いと理由は、[extract/NOTES-content.md](../../extract/NOTES-content.md) の8章と、[extract/table.json](../../extract/table.json) の各部品の `note` にあります。
