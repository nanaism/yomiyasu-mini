# 測定の記録

本体 yomiyasu v2.2.2 と yomiyasu-mini 1.0.0 に同じ原稿を推敲させ、書き直した文を本体 v2.2.2 の検査で数えました。1本ごとの数は [results.json](./results.json) にあります。

## 測り方

- 原稿: 本体 v2.2.2 の `tests/corpus/` から、`raw_ai/` の26本、`blacklist_ai/` の24本、`edge_cases/` の1本（`edge_kiku_45`）。どれも1回ずつ推敲させました。
- 推敲させたもの: Codex CLI 0.163.0 の gpt-6-astra で、effort は high、速さは既定のままです（service_tier を渡していません）。本体と mini で同じモデルと設定を使いました。
- 頼み方: 1本ごとに空の作業フォルダを作り、原稿を `draft.md` として置き、スキルを `.agents/skills/` の下に写しました。そのうえで「`$yomiyasu:yomiyasu` で draft.md を推敲し、最終稿を out.md に保存してください。」と頼みました（mini は `$yomiyasu-mini`）。読み込まれたスキルが測るスキルだけであることを、1本ごとに Codex の記録で確かめています。
- 数え方: 原文と最終稿を本体 v2.2.2 の `yomiyasu_diff.py 原文 最終稿 --fail-on meaning-risk --json` に渡しました（`--doc-type` と `--stance` は渡していません）。「数える恐れ」は、`--fail-on meaning-risk` が数える意味が変わる恐れです。残った候補は `yomiyasu_lint.py 最終稿 --json` の warn 以上で数えました。書き換えた量は、`difflib.SequenceMatcher(autojunk=False)` で一致しない区間ごとに原文と最終稿の長いほうの字数を足し、原文の空白を除いた字数1,000字あたりにした値です。

## 途中で止めたこと

初めは約640本を測るつもりでした。本体と mini を115本ずつ、AIの文の50本でもう1回ずつ、スクリプトのない mini を50本、規則か参照ファイルを外した写し10種を `raw_ai/` の26本ずつ測る組み方でした。進み方が遅く時間が足りなくなったので、本体と mini の1回目の102本（51組）で止めました。

スクリプトのない mini と、規則か参照ファイルを外した写しは回していません。そのため、測った数字をもとに外した規則はありません。どの組も1回ずつの結果です。

## 恐れを1件ずつ読んだ結果

次の2件は、本体と mini が同じ文を同じように書き直したもので、どちらにも1件ずつ出ています。

- `raw_ai/07_code_review_sonnet_default`（文の種類）: 「…業務ルールだけを持たせます。」を「…業務ルールだけを持たせてください。」にしています。説明の形で書かれた提案を、依頼の形に上げました。
- `raw_ai/09_listicle_patterns`（数）: 「重要なポイントは3つです。」を「速度、互換性、管理の3点が重要です。」にしています。数は同じで、すぐあとの箇条書きの頭の語（速度、互換性、管理）をこの文に移し、箇条書きからは外しました。意味は変わっていません。

mini にだけ出たのは、次の2件です。

- `blacklist_ai/05_comparison_sonnet_casual`（数）: 「BFFを1枚挟む」を「BFFを1層設ける」にしています。数の1は同じで、助数詞を「枚」から「層」に、動詞を「挟む」から「設ける」に替えました。どちらも BFF を1つ置くことを言っていて、意味は変わっていません。
- `blacklist_ai/07_code_review_sonnet_casual`（文の種類）: 「…サービスからはHTTPの詳細が見えないようにします。」を「…見えないようにしてください。」にしています。原稿では「提案は三つです。」のあとに「まず…切り出してください。」「次に…ようにします。」が続き、mini は2つ目の提案の文末を1つ目にそろえて依頼にしました。説明の形の提案を依頼に上げたので、言い切りの強さが1段上がっています。mini は返事の「変えたところ」にこの変更を書き、書き手に確かめたい点には出していません。同じ文を本体は「…ようにしましょう。」にしていて、diff はこれを数えていません。

diff が数えない所の書き換えもありました。同じ `blacklist_ai/07` で、mini は「全部このメソッドを触ることになります」を「どちらの場合もこのメソッドを変更することになります」にしています。本体も「触る」を「変更する」にしました。

## 入れた決まりと外したもの

意味を守る決まりは SKILL.md の本文に置き、測定で外さない部品にしています。

意味の保持（最優先ルール）、情報が足りないときの暫定文、専門用語と名称の扱い、言い直しテストは、本体の文をそのまま写しました。置き換えたのは、mini にない道具やファイルを指す句だけです。情報を足さないことは、本体の節の最初の2段落をそのまま写し、AIへの指示が本文に残った文の段落を短く書き直しました（全文は `references/rules.md`）。言い切りの強さを上げないことは本体の「文書の立場と文末」から、条件・否定・因果・時系列を保つことは「段落と文の論理構造（つながり）」から、短く書き直して入れました。細部は参照ファイルに写しています。

本体の SKILL.md のほかの節は、短く書き直して SKILL.md に置き、SKILL.md に入らなかった文と事例を `references/rules.md` と `references/doc-types.md` に写しました。

外したのは、おもに mini にない道具に関わる手順と出力の欄です。lint の規則の名前、diff の文体の硬化と勢いの検査、check の実行の記録（run と verify）、資料から事実を補う手順と「事実の確かめ」の欄、lint が読む語のファイル（`references/lists/`）、Step 5「提出の前の照合」がこれに当たります。Step 5 のうち、残った直訳語と flag.txt の語を見直す確かめだけは、Step 4 の目で見る点検に書き直して入れました。ほかに、本体の「情報の不増補」の、相対の日付に日付を添える段落を入れていません。参照ファイルのうち、slop-catalog.md の3章（lint の語彙と同じ一覧）、gemini-syntax.md の調査の節と原則2〜14（SKILL.md や写した節と重なる）、persona.md と audience.md の一部の章（読む場面と決め方、読者像、例など）も写していません。部品ごとの扱いと理由は、[extract/NOTES-content.md](../extract/NOTES-content.md) の8章と、[extract/table.json](../extract/table.json) の各部品の `note` にあります。
